# Experimental Protocol (Midpoint, updated)

Team ASB: Srinidhi Ganeshan, Ruchi Kapse, Siddhartha Tamma

## Setup
- **Baseline:** ASB memory-poisoning attack (`config/MP.yml`), `memory_attack` injection, `combined_attack` attack type.
- **Model:** `ollama/llama3.1:8b` (Ollama default 4-bit quantization), temperature 0.0 (ASB default).
- **Hardware:** team members' local machines via Ollama. *Change from proposal:* we no longer use a dedicated 24GB GPU, so the run budget below is sized for local inference.

## Variables
| Variable | Values | Owner |
|---|---|---|
| Poisoned-memory fraction p | 0, 5, 10, 25, 50 % | Srinidhi |
| Retrieval depth k | 1, 3, 5 | Ruchi |
| Full grid p × k | 15 cells | Siddhartha |

## Memory databases
- **Poisoned pool:** `memory_db/direct_prompt_injection/combined_attack_gpt-4o-mini` (462 entries, all of which contain an attacker tool in the stored plan).
- **Clean pool:** generated by running the clean config with `write_db: true` into a separate DB, so the plans contain no attacker tools.
- **Mixed DBs:** for each p, sample a fixed total of N entries with p% from the poisoned pool and the rest from the clean pool. N is the same for all p. Fixed sampling seed: 0.

## Baseline changes needed
1. **Retrieval depth.** `react_agent_attack.py` (`search_memory_instruction`) currently uses only `memory[0]`, so k is fixed at 1. This will be changed to retrieve and insert the top-k entries.
2. **Clean memories.** The repo only has poisoned memories, so a clean pool has to be generated before p can be varied.
3. **Clean control config.** `clean.yml` has `defense_type: dynamic_prompt_rewriting` set. This will be removed for the no-poison control.

## Task split
ASB has 10 agents with 5 to 6 tasks each and 40 attacker tools per agent.
- **Dev (tuning N and checking runs):** `financial_analyst_agent`, `system_admin_agent`
- **Held-out (reported results):** the other 8 agents
- **Per cell:** 2 attacker tools per agent (1 aggressive, 1 non-aggressive) × 2 tasks per agent, which gives 32 runs per cell on held-out (8 agents × 2 tools × 2 tasks).
- The same tool and task selection is used in every cell.

## Metrics (ASB definitions)
- **ASR:** fraction of attacked runs where the agent calls the attacker tool (`Attack Successful`).
- **PNA:** task success rate in the clean control, p = 0 (`Original Task Successful`).
- **NRP:** PNA × (1 − ASR).
- **Also logged:** refusal rate and memory-found rate.

## Logging
- Each run sets `suffix: p<p>_k<k>` in its YAML, so the output files are named `..._p10_k3.csv` under `logs/memory_attack/llama3.1_8b/`.
- `eval_metrics.py` reads all of these logs and writes `results/summary.csv`, with one row per (p, k).

## Sanity check
- **Clean control:** p = 0, clean memory DB, no defense.
- **Expected result:** ASR = 0, and PNA close to ASB's reported value for Llama-3.1-8B.
- `eval_metrics.py` warns automatically if the clean ASR is above 0.
